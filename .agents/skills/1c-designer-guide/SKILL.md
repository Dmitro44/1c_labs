# Как вести пользователя-новичка в Конфигураторе

Пользователь не разбирается в 1С и хочет понимать, что происходит. Правило проекта:

> **Сначала — инструкция «как это сделать самому в Конфигураторе», потом — изменения.**

Инструкция пишется для человека, который видит Конфигуратор впервые: с названиями окон, вкладок,
кнопок и свойств. Отдельно объясняется **смысл** задачи: что за данные меняются и почему кнопка
делает именно это. В конце — что изменится в `src/cf` и как проверить результат в Предприятии.

## 0. Полный флоу задачи

1. **Понять смысл** — что кнопка/правка должна сделать в терминах данных, а не интерфейса
   (создать документ? открыть справочник? выбрать строку? записать регистр?).
2. **Проверить выполнимость** — таблица значений с `ChangeRowSet=false` и запросы не дают
   «просто добавить строку»; регистр с подчинением регистратору нельзя писать напрямую.
3. **Напечатать инструкцию** для Конфигуратора по шаблону §4.
4. **Пользователь делает сам** и задаёт вопросы — отвечать по §6.2 (команда объекта/формы),
   §6.3 (диалог создания обработчика), §6.4 (колбэк после закрытия формы).
5. **Сохранение и применение**: `Ctrl+S` → **F7** «Обновить конфигурацию базы данных».
6. **Проверка в Предприятии** (в проекте — веб-клиент) по конкретному пути.
7. **Синхронизация `src/cf`** (вручную тем же изменением, не выгрузкой формы) → `apply-config.sh`
   → `CheckConfig` → проверка → остановить `ibsrv` (§7).

## 1. Два режима работы

| Пользователь сказал | Что делает агент |
|---|---|
| «Сделай ты» / «исправь» | печатает инструкцию для Конфигуратора **и** правит `src/cf` |
| «Объясни, я сам» / «как в Конфигураторе» | **только** инструкция; файлы не меняет, базу не трогает, ждёт |

В режиме «сделай ты» инструкция всё равно печатается — коротко, но полностью, чтобы
пользователь мог проверить руками или повторить позже.

## 2. Сначала смысл, потом кнопки

Прежде чем писать шаги, объяснить простыми словами, **что за данные** и **кто есть кто**.
Пример из этого проекта (форма «Подбор замещающих»):

| Роль | Где живёт |
|---|---|
| **Замещающий** — кого принимают на работу | поле «Сотрудник» в документе «Приём на работу» (шапка) |
| **Отсутствующий** — кого заменяют (болеет / в отпуске) | таблица «Отсутствующие» в форме подбора |

Что важно проговорить:

- форма подбора **ничего не создаёт**, она только показывает отсутствующих и возвращает выбор
  в документ (`ОповеститьОВыборе` → `ОбработкаВыбора`);
- список отсутствующих — **результат запроса** (`РегистрСведений.Отпуск` + `Документ.Больничные.Сотрудники`),
  поэтому «добавить строку» в него нельзя;
- «Добавить» в такой форме = **зарегистрировать новое отсутствие**, после чего человек появится
  в списке. В конфигурации это документ «Больничные» (отпуска — записью регистра «Отпуск»,
  у него нет своего документа).

Если название кнопки расходится со смыслом («Добавить замещающего» вместо «Добавить отсутствие») —
сказать об этом прямо и предложить переименовать заголовок; код при этом не меняется.

Варианты «добавления», которые надо различать:

| Что хочет пользователь | Что должна делать кнопка | Подходит ли форма подбора |
|---|---|---|
| зарегистрировать отсутствие (больничный) | открыть `Документ.Больничные.Форма.ФормаДокумента` | да |
| зарегистрировать отпуск | открыть регистр «Отпуск» (своей формы нет — стандартная форма списка) | да |
| добавить сотрудника в справочник | открыть `Справочник.Сотрудники.Форма.ФормаЭлемента` | нет — на список отсутствующих не влияет |

Сквозной сценарий, который надо показать пользователю целиком:

1. «Приёмы на работу» → «Создать»;
2. **Сотрудник** = кого принимают (это замещающий);
3. **Метод приёма** = «Замещение» → появляется блок «Замещение»;
4. «Подобрать замещающих» → список отсутствующих;
5. нет нужного человека → «Добавить» → больничный → закрыть → человек в списке;
6. выбрать строку → «Выбрать» → заполнился «Отсутствующий сотрудник»;
7. провести документ → записи в регистрах замещения.

## 3. Обязательные части инструкции

1. **Результат** — что получится после шагов.
2. **Навигация по дереву** — путь от корня: `Документы → ПриемНаРаботу → Формы →
   ФормаПодбораЗамещающих`; что открыть двойным щелчком.
3. **Где именно нажимать** — вкладка редактора формы (`Форма`, `Реквизиты`, `Команды`,
   `Параметры`, `Модуль`), область (`командная панель таблицы`), действие (ПКМ → «Добавить»).
4. **Значения свойств** — таблицей: свойство → значение.
5. **Выбор в диалогах** — какой именно пункт нажать (например, «Создать на клиенте»)
   и почему (§6.3).
6. **Код** — куда вставить (область модуля), готовый текст, что заменить; отдельно назвать
   процедуру-колбэк и её `Экспорт` (§6.4).
7. **Сохранение и обновление** — `Ctrl+S`, затем **F7** «Обновить конфигурацию базы данных».
8. **Проверка** — как открыть в Предприятии и что увидеть.
9. **Связь с `src/cf`** — какие файлы изменятся и почему после ручных правок нужно позвать
   агента (иначе следующий `apply` затрёт ручную работу).
10. **Откат** — `Ctrl+Z` / закрыть форму без сохранения / `git checkout -- <файл>`.

## 4. Шаблон ответа

````markdown
## Как сделать это в Конфигураторе

**Что получится:** <одно предложение>

**Смысл:** <кто такой замещающий/отсутствующий, откуда берутся строки таблицы,
почему нельзя добавить строку вручную>

**1. Открыть форму**
Конфигуратор → «Открыть конфигурацию» → дерево:
`Документы → ПриемНаРаботу → Формы → ФормаПодбораЗамещающих` → двойной щелчок.

**2. Добавить команду формы**
Вкладка **«Команды»** редактора формы → ПКМ → **«Добавить»**.
| Свойство | Значение |
|---|---|
| Имя | `ДобавитьЗамещающего` |
| Заголовок | `Зарегистрировать отсутствие` |
| Действие | `ДобавитьЗамещающего` → в диалоге «**Создать на клиенте**» |

**3. Поставить кнопку на панель**
Вкладка **«Форма»** → таблица `Отсутствующие` → её командная панель → ПКМ → **«Добавить»** →
свойство **«Команда»** = `ДобавитьЗамещающего`.

**4. Вставить код**
Вкладка **«Модуль»** → область «Обработчики команд формы»:
```bsl
&НаКлиенте
Процедура ДобавитьЗамещающего(Команда)
	ОповещениеОЗакрытии = Новый ОписаниеОповещения("ПослеДобавленияЗамещающего", ЭтотОбъект);
	ОткрытьФорму("Документ.Больничные.Форма.ФормаДокумента", , ЭтотОбъект, , , , ОповещениеОЗакрытии);
КонецПроцедуры

&НаКлиенте
Процедура ПослеДобавленияЗамещающего(РезультатЗакрытия, ДопПараметры) Экспорт
	ЗаполнитьОтсутствующих();
КонецПроцедуры
```

**5. Сохранить и обновить**
`Ctrl+S` → **F7** «Обновить конфигурацию базы данных» → «Принять».

**6. Проверить**
Приёмы на работу → «Создать» → Метод приёма «Замещение» → «Подобрать замещающих» →
кнопка открывает «Больничные» → закрыть → список перезаполнился.

**Что изменится в исходниках:**
`src/cf/.../Ext/Form.xml` (кнопка + команда), `src/cf/.../Ext/Form/Module.bsl` (2 процедуры).
После ручной правки сказать — приведу `src/cf` в соответствие, иначе следующий `apply` затрёт.

**Откат:** `Ctrl+Z` до сохранения; после — `git checkout -- <файл>`.
````

## 5. Словарь для новичка

- **Дерево конфигурации** — левая колонка Конфигуратора (Справочники, Документы, Регистры…).
- **Панель свойств** — правая колонка; меняется по выделенному объекту.
- **Редактор формы** — отдельное окно (двойной щелчок по форме), вкладки `Форма`, `Реквизиты`,
  `Команды`, `Параметры`, `Модуль`.
- **Команда объекта** — команда в ветке `Документы → ПриемНаРаботу → Команды`; живёт в объекте,
  обработчик в модуле команды.
- **Команда формы** — команда на вкладке «Команды» редактора формы; обработчик в модуле формы,
  доступна кнопкам этой формы.
- **Панель элементов** — список слева в редакторе формы.
- **Командная панель** — серая полоса над таблицей/формой с кнопками.
- **F7 / «Обновить конфигурацию базы данных»** — применить правки, чтобы их увидело Предприятие.
- **Предприятие** — режим проверки результата (в проекте — веб-клиент).
- **Контекст формы** — данные формы (`Объект`, реквизиты, `Элементы`), которые передаются на
  сервер при вызове `&НаСервере`-процедуры.
- **Оповещение (ОписаниеОповещения)** — «записка»: какую процедуру вызвать, когда форма
  закроется/операция завершится.

## 6. Типовые операции

### 6.1. Кнопка с собственной командой формы

1. Открыть форму объекта двойным щелчком.
2. Вкладка «Команды» → ПКМ → «Добавить» → Имя / Заголовок / **Действие**;
   в диалоге создания обработчика — «**Создать на клиенте**» (§6.3).
3. Вкладка «Форма» → нужная таблица или панель формы → ПКМ по командной панели → «Добавить» →
   свойство «Команда» = созданная команда.
4. Вкладка «Модуль» → обработчик + колбэк (§6.4).
5. `Ctrl+S` → F7 → проверка.

Альтернативный путь: ПКМ по командной панели → «Добавить» → у кнопки в свойстве «Команда» нажать
кнопку выбора (`…`) → там можно **создать команду формы** — она сразу получит правильный тип.

### 6.2. Команда объекта или команда формы — как отличить

Самая частая ошибка новичка: добавили команду в ветке объекта и удивляются набору свойств.

| Свойства, которые видно | Что это | Годится кнопке формы? |
|---|---|---|
| `Тип параметра команды`, `Режим использования параметра`, `Модуль команды`, `Группа`, `Отображение`, `Подсказка` | **команда объекта** (ветка `Команды` у документа/справочника) | нет |
| `Заголовок`, `Картинка`, `Сочетание клавиш`, `Действие`, `Только в командной панели формы`, `Изменяет данные` | **команда формы** (вкладка «Команды» редактора формы) | да |

Если пользователь уже создал команду объекта:
1. дерево → `Документы → ПриемНаРаботу → Команды` → выделить → `Del`;
2. открыть форму двойным щелчком по `Формы → ФормаПодбораЗамещающих`;
3. вкладка «Команды» **этого окна** → ПКМ → «Добавить» → снова заполнить Имя/Заголовок/Действие.

Признак правильного окна: заголовок «ФормаПодбораЗамещающих» и вкладки `Форма | Реквизиты |
Команды | Параметры | Модуль` внизу.

### 6.3. Диалог «Создание обработчика команды» (клиент / сервер)

В свойстве «Действие» нажимают кнопку выбора — Конфигуратор спрашивает, что создать.
В инструкции всегда указывать пункт и причину.

| Вариант | Что создаёт | Когда выбирать |
|---|---|---|
| **Создать на клиенте** | `&НаКлиенте Процедура Имя(Команда)` | открыть форму, показать предупреждение/вопрос, вызвать уже существующую серверную процедуру формы (**обычный выбор**) |
| Создать на клиенте и процедуру на сервере без контекста | `&НаКлиенте` + `&НаСервереБезКонтекста` | тяжёлый запрос/расчёт, данные формы не нужны, важна скорость |
| Создать на клиенте и процедуру на сервере | `&НаКлиенте` + `&НаСервере` | на сервере нужны `Объект`, реквизиты или `Элементы` формы (передаётся весь контекст — медленнее) |

- **Клиент** — код у пользователя: `ОткрытьФорму`, `ПоказатьВопрос`, `ПоказатьПредупреждение`,
  работа с элементами формы.
- **Сервер без контекста** — данные формы не видит, общается только параметрами; дешевле всего.
- **Сервер с контекстом** — видит всё, но каждый вызов тащит контекст; в цикле — плохо.

Правило: по умолчанию «**Создать на клиенте**». Серверные варианты — только при реальной
необходимости. Лишние пустые заготовки удалять.

Важно: `&НаСервере`-процедуры формы вызываются из клиента **без** `Экспорт` (`Экспорт` нужен
только для вызова из других модулей). Поэтому обёртка над уже существующей серверной процедурой
не нужна.

### 6.4. Колбэк после закрытия формы (`ОписаниеОповещения`)

`ОткрытьФорму` не ждёт закрытия — она сразу возвращает управление. Чтобы обновить данные
**после** работы пользователя, передают 7-м параметром описание оповещения:

```bsl
ОповещениеОЗакрытии = Новый ОписаниеОповещения("ПослеДобавленияЗамещающего", ЭтотОбъект);
ОткрытьФорму("Документ.Больничные.Форма.ФормаДокумента", , ЭтотОбъект, , , , ОповещениеОЗакрытии);
```

```
клик по кнопке
  └─ Обработчик(Команда) → открыл форму, сразу вышел
       └─ [пользователь работает в форме]
            └─ форма закрылась
                 └─ ПослеДобавленияЗамещающего() → ЗаполнитьОтсутствующих()
```

| Параметр колбэка | Значение |
|---|---|
| `РезультатЗакрытия` | что вернула форма; при обычном закрытии — `Неопределено` |
| `ДопПараметры` | 3-й аргумент `Новый ОписаниеОповещения(...)`, по умолчанию `Неопределено` |

Обязательные условия:
- у колбэка стоит `&НаКлиенте` и **`Экспорт`** (вызывает платформа по имени, извне модуля);
- имя в строке совпадает с именем процедуры буква в букву;
- процедура в том же модуле, чей объект передан (`ЭтотОбъект`);
- вызывать обновление сразу после `ОткрытьФорму` бессмысленно — форма немодальная,
  пользователь ещё ничего не ввёл.

Параметры `ОткрытьФорму`: `(ИмяФормы, Параметры, Владелец, Ключ, ОкноОткрытия, Толчок, Оповещение)`.

### 6.5. Прочие операции

**Обычный реквизит на форме**
1. Вкладка «Реквизиты» → ПКМ → «Добавить» → Имя, Тип.
2. Вкладка «Форма» → перетащить реквизит на место (или ПКМ → «Добавить» → «Поле»).

**Новый объект (справочник/документ/регистр)**
1. ПКМ по ветке «Справочники»/«Документы»/«Регистры» → «Добавить».
2. Имя — латиницей, Синоним — по-русски.
3. Вкладки объекта: «Данные», «Формы», «Прочее» → F7.

**Изменение поведения формы**
Вкладка «Модуль» → найти обработчик (`ПриСозданииНаСервере`, `…ПриИзменении`) → код → `Ctrl+S` → F7.

### 6.6. Области (`#Область`) в инструкциях не давать

**Правило проекта: в тексте инструкции для ручного ввода в Конфигураторе не писать
`#Область` / `#КонецОбласти`.** Код выдавать без областей — голыми процедурами.

Почему (проверено на `ФормаПодбораОснований`): строка области, набранная или вставленная
вручную, не компилируется —

```
{Документ.ПриемНаРаботу.Форма.ФормаПодбораОснований.Форма(51,10)}:
Ошибка в операторе препроцессора
#Область <<?>>СлужебныеПроцедурыИФункции (Проверка: Сервер)
```

Маркер `<<?>>` стоит ровно перед именем области: платформа распознала директиву, но не смогла
прочитать имя. Причины, которые дают именно это сообщение:

| Причина | Как выглядит |
|---|---|
| невидимый символ в имени (NBSP `U+00A0`, мягкий перенос `U+00AD`, zero-width `U+200B`) | визуально не отличить от обычного текста; почти всегда приезжает копипастом |
| имя области не одним словом (пробел, табуляция внутри) | `#Область Моя Область` |
| мусорный символ вместо пробела между `#Область` и именем | ошибка указывает на имя, а не на директиву |

Области сами по себе платформой разрешены (и даже вкладываются друг в друга), но у новичка в
Конфигураторе они дают ошибку компиляции, которую он не может диагностировать, и он застревает
на ровном месте. Поэтому:

- в инструкции — **никаких** `#Область`; если по структуре нужен сервисный блок, писать
  комментарий `// Служебные процедуры` вместо директивы;
- если пользователь сам хочет область — единственный безопасный способ: выделить процедуру →
  ПКМ → **«Обернуть в область»** → имя ввести в диалоге (редактор вставит корректные символы);
- при ошибке «Ошибка в операторе препроцессора» первый совет — **удалить строки области**
  (`#Область` и парную `#КонецОбласти`), это косметика, на работу кода не влияет;
- в `src/cf` области в модулях остаются как есть — это файлы, а не ручной ввод; из исходников
  строки области в инструкцию не копировать.

## 7. Осторожно в этом проекте

- `src/cf` — **источник истины**. Ручные правки в Конфигураторе живут только в базе и исчезнут
  при следующем `apply-config.sh`.
- Не выгружать формы из Конфигуратора в `src/cf` без проверки: в базе бывают следы сохранений
  из Дизайнера (кнопка привязана к `StandardCommand.Add` вместо `Form.Command.*`) — выгрузка
  затрёт правильные привязки.
- После ручных правок — синхронизировать `src/cf` **тем же изменением вручную**, а не выгрузкой.
- Кнопки таблиц с `ChangeRowSet=false` (таблицы значений) стандартными командами не работают —
  нужна команда формы с обработчиком.
- **Не советовать `#Область`** в инструкциях для ручного ввода (§6.6): строка области из копипаста
  даёт «Ошибка в операторе препроцессора» и модуль не компилируется. Код в инструкции — без областей.
- Применение конфигурации закрывает окна 1С — спрашивать разрешение заранее.
- После работы с базой — остановить `ibsrv` (`web-down.sh`), даже если проверка не удалась.
