# Правила проекта (1С, конфигурация КадровыйУчетБГУИР)

## Обязательное правило: освобождать базу после работы

После ЛЮБОЙ работы с базой 1С останавливать все поднятые мной процессы, работающие с базой:

```bash
bash .agents/skills/1c-web-ui-test/scripts/web-down.sh   # остановить ibsrv, проверить порт 8314
```

- База файловая (`Labs_1s`); оставленный веб-сервер ibsrv блокирует её и мешает пользователю (Конфигуратор) и применению конфигурации.
- Этот шаг обязателен всегда, включая случаи, когда проверка не удалась или прервалась — останавливать в любом случае.
- Оставить сервер работающим можно ТОЛЬКО по явной просьбе пользователя, и тогда сообщить ему команду остановки.
- В финальном ответе пользователю подтверждать: база свободна / сервер остановлен.

## Правило: сначала инструкция для Конфигуратора — потом правки

Пользователь не разбирается в 1С, поэтому перед любыми изменениями (код, формы, реквизиты, команды,
кнопки, объекты метаданных, скрипты) сначала выдать пошаговую инструкцию, **как сделать то же самое
вручную в Конфигураторе**: путь по дереву конфигурации, вкладки редактора формы, значения свойств,
`Ctrl+S` и «Обновить конфигурацию базы данных» (F7), проверка в Предприятии и откат.
Только после этого менять файлы. Если пользователь говорит «объясни, я сам» — файлы не трогать.
Подробности, шаблон и словарь терминов — навык `1c-designer-guide`.

Полезные навыки проекта (`.agents/skills/`): `1c-designer-guide` (инструкция для Конфигуратора до правок), `1c-dev-workflow` (полный цикл: объекты, формы, кнопки, отчёты, применение и проверка), `1c-config-sync` (применение src/cf через ibcmd), `1c-form-build` (сборка форм из DSL), `1c-web-ui-test` (веб-клиент), `1c-platform-quirks` (грабли 8.5).
